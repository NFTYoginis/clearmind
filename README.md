# ClearMind: The Other Side

> *Find what's really going on. A calmer way through.*

ClearMind is a no-account web tool that takes a person from **fog to clarity** on something weighing on them. It is a **state-change tool, not a decision tool** — the person crosses from the *apparent* problem to the *actual* problem and leaves with a written commitment, the **crossing document**.

The whole design fits in seven words: **lead with the feeling, deliver the artifact.**

> **North star:** ClearMind does not help people make decisions. It helps people understand *what decision they are actually making.* Recognition — *"oh, THAT's what this is really about"* — is the product; the written next step is what makes it stick.

---

## How it works (the short version)

One seamless conversation moves the person across four movements without ever showing the seams:

| Movement | What the person feels | What's happening backstage *(never named to them)* |
|----------|----------------------|----------------------------------------------------|
| **Fog** | Heard | Coaching-style extraction — getting under the apparent problem |
| **Orientation** | Settled, knows what they want | A desires/gratitude/loves priming that settles the nervous system and surfaces wants |
| **Formation** | Sees the real fork | A decision-structuring method (outcomes → options → consequences → evaluate → mitigate → resolve) |
| **Crossing** | Moving, holding a commitment | Recognition converted into a written next step — the crossing document |

The mechanics are **always invisible.** No acronyms, no stage names, no "choose a tool" menu — the person experiences a single warm, attentive presence. The runtime watches **five signals** every turn (`reference/signals.md`) and adapts to where *this* person actually is: one person sits twenty minutes in the fog; another arrives already knowing what they want and goes straight to the fork. **Signals, not stages.**

Every completed session ends with a crossing document. If acute distress surfaces, the **crisis off-ramp** overrides everything and points to real help (`reference/crisis-offramp.md`).

## Architecture — repo-as-live-system-prompt

The ICM folders *are* the system prompt. There is no separate "config." A small build step concatenates them in order into the prompt the runtime feeds to Claude.

```
clearmind/
├── identity.md            ← who ClearMind is (persona layer of the system prompt)
├── rules.md               ← the behavioral contract (Rule 0, off-ramp, register, refusal gates)
├── examples.md            ← three full worked sessions (also few-shot in the prompt)
├── reference/
│   ├── signals.md         ← the five signals + the routing brain ("signals, not stages")
│   ├── crossing-document.md ← the artifact spec + the ```crossing sentinel format
│   ├── crisis-offramp.md  ← acute-distress detection + warm handoff (overrides everything)
│   ├── attribution.md     ← honest credit to the methods' originators
│   └── frameworks/        ← the four backstage methods, each in ICM shape
│       ├── fog-coaching/        (identity · rules · examples)
│       ├── orientation-10-10-10/
│       ├── formation-oocemr/
│       └── crossing/
├── scripts/
│   └── build-prompt.mjs   ← reads the ICM folders → emits the system prompt
├── runner/
│   ├── cli.mjs            ← thin terminal runner (proves the loop; no SDK, no node_modules)
│   └── gate/*.json        ← scripted gate transcripts (fog→crossing, crisis)
├── worker/                ← the hosted no-account web tool (Cloudflare Worker + chat UI)
│   ├── wrangler.jsonc
│   ├── src/index.js       ← streaming proxy: server-side key + budget/abuse guards
│   ├── src/system-prompt.generated.js  ← AUTO-GENERATED by build-prompt.mjs
│   └── public/index.html  ← the calm, single-input chat UI + savable crossing card
└── docs/
    └── index.html         ← the v1 GitHub Pages landing
```

**To change ClearMind's behavior, edit the ICM files — then regenerate the prompt** (`npm run build:prompt`, or it runs automatically on `dev`/`deploy`). The thin runner reads the ICM files live; the Worker uses the generated module.

## Two ways to run it

### 1. As the hosted no-account web tool (the product)

A Cloudflare Worker serves the chat UI and proxies streamed Claude responses. The Anthropic API key lives as a **Worker secret** and is never exposed to the client.

```bash
cd worker
npm install
echo "ANTHROPIC_API_KEY=sk-ant-..." > .dev.vars   # local dev only — gitignored, never commit
npm run dev                                        # builds the prompt, then wrangler dev

# deploy (operator-side — see DEPLOY below)
wrangler secret put ANTHROPIC_API_KEY              # set the production secret once
npm run deploy                                     # builds the prompt, then wrangler deploy
```

Baked in: server-side key, a per-IP rate limit (`30 req / 60s`), and budget guards (max turns, max message length, max transcript size, `max_tokens` cap) — because a public no-account tool pays inference per session.

### 2. As an ICM specialist inside a Claude Project

ClearMind is also a self-contained ICM specialist. Load `identity.md`, `rules.md`, `examples.md`, and the `reference/` folder into a Claude Project's knowledge, and the project *is* ClearMind — the same signal-watching, invisible-mechanics conversation, by hand.

### Thin runner (for local testing / proving the loop)

```bash
ANTHROPIC_API_KEY=sk-ant-... node runner/cli.mjs                          # interactive
ANTHROPIC_API_KEY=sk-ant-... node runner/cli.mjs --script runner/gate/fog-to-crossing.json
```

The runner reads the ICM folders live, drives a real session with raw `fetch` (no SDK), and renders the crossing card in the terminal. It uses the **identical request shape** as the Worker.

## Cost & model

`CLEARMIND_MODEL` (a Worker var in `wrangler.jsonc`) selects the model. Default: **`claude-sonnet-4-6`** — strong and budget-appropriate for a public tool we pay for per session. Flip to **`claude-opus-4-8`** for maximum quality (≈1.7× the per-token cost). One-line change, no code edits.

The ~17k-token system prompt is byte-stable across all users and turns, so it's sent with `cache_control: ephemeral` and served from cache (~0.1× cost) on every turn after the first — verified in testing (`cache_read` hits on turns 2+).

## Safety

ClearMind is a **thinking companion — not therapy and not a crisis line.** Surfacing the real problem can land heavier than the person arrived, so the runtime watches for acute distress on every turn and, when it sees it, stops the method and hands off warmly to real help:

- **[Find A Helpline](https://findahelpline.com)** — free, confidential helplines in 130+ countries (ThroughLine).
- **[IASP — Crisis Centres & Helplines](https://www.iasp.info/crisis-centres-helplines/)** — global directory by country.
- "If you're in immediate danger, call your local emergency number."

The off-ramp produces no crossing document and runs no framework — it's a soft door, not a wall. See `reference/crisis-offramp.md`.

## Attribution

ClearMind's contribution is the *sequencing and concealment* — reading a person's signals, summoning the right method at the right moment, keeping it all backstage, and ending in a written crossing. The methods themselves are borrowed and credited:

- **The fog / coaching questions** draw on the coaching-question tradition, most directly **Michael Bungay Stanier**'s *The Coaching Habit* — the first problem named is rarely the real one.
- **The formation method** is **Tony Robbins**'s **OOCEMR** decision framework (Outcomes → Options → Consequences → Evaluate → Mitigate → Resolve).
- **The orientation priming** (desires / gratitude / loves) is a common nervous-system-settling practice with no single claimed originator.
- **The crossing** reflects the broad, well-supported principle that people act on commitments, not analyses.

These are credited here and in `reference/attribution.md`. They are **never named to the person** during a session. Full detail: `reference/attribution.md`.
